# Spam SMS Detector — Ensemble ML + FastAPI + JWT Auth

A full-stack spam/scam SMS classifier. A stacked ensemble of four ML models
plus rule-based heuristics decides spam vs ham; a FastAPI backend serves
predictions and JWT-authenticated scan history; a lightweight vanilla-JS
frontend (no build step required) provides the UI.

## How it works

**Classification pipeline** (`app/ml/`):
- 3 base models trained on word-level TF-IDF: Naive Bayes, Linear SVM, Random Forest
- 1 base model trained on character n-gram TF-IDF (catches obfuscated spelling
  and modern link-based patterns word-level features miss, e.g. `fr33`, `bit.ly/x`)
- 8 rule-based heuristic features (URLs, shortened links, urgency/prize
  language, phone numbers, currency symbols, punctuation/caps patterns)
- A KNN meta-model trained on stacked [4 model votes + 8 heuristic flags],
  using cross-validated predictions during training to avoid data leakage

On the held-out test set this reaches **99.1% accuracy, 93.9% recall** on
spam, improving on every individual model in the ensemble.

**Backend** (`app/`): FastAPI, JWT auth (`python-jose` + `passlib`), SQLite
via SQLAlchemy. `/api/predict` works for anyone; if the caller is logged in,
the result is also saved to their history. `/api/history` requires login.

**Frontend** (`app/static/`): plain HTML/CSS/JS served directly by FastAPI —
no Node/npm, no build step. Talks to the API with `fetch`, stores the JWT
in `localStorage`, sends it as a Bearer token — the same pattern a React
app would use, just without the extra tooling.

## Known limitations (read before treating this as production-ready)

- The training data (SMS Spam Collection, ~5,500 messages) is from
  **2011-2012**. It doesn't reflect modern phishing/scam phrasing on its
  own — the heuristic layer (link/urgency detection) exists specifically to
  cover this gap, but a from-scratch retrain on current data would still
  generalize better.
- The KNN meta-model was tuned to a fixed `n_neighbors=5` and evaluated on
  one train/test split — solid for a portfolio project, not
  hyperparameter-search-validated for production.
- SQLite is fine for local/demo use; a real deployment with concurrent users
  would want Postgres.

## Setup — from a fresh clone

**1. Clone and enter the project**
```bash
git clone <your-repo-url>
cd spam-sms-detector
```

**2. Create and activate a virtual environment**

Windows (PowerShell):
```powershell
python -m venv venv
venv\Scripts\Activate.ps1
```

Mac/Linux:
```bash
python3 -m venv venv
source venv/bin/activate
```

**3. Install dependencies**
```bash
pip install -r requirements.txt
```

**4. Set up your environment file**
```bash
cp .env.example .env      # Windows: copy .env.example .env
```
Then open `.env` and replace `SECRET_KEY` with a real random value:
```bash
python -c "import secrets; print(secrets.token_hex(32))"
```
Paste the output as `SECRET_KEY` in `.env`.

**5. Train the model (generates `app/artifacts/`)**

This is a required one-time step after cloning — model files aren't stored
in git, they're regenerated locally. Takes under a minute.
```bash
python -m app.ml.train
```
You should see accuracy/precision/recall printed, ending with
`All artifacts saved to .../app/artifacts`.

**6. Run the app**
```bash
uvicorn app.main:app --reload
```

**7. Open it**

Go to **http://127.0.0.1:8000** in your browser. Interactive API docs are
at **http://127.0.0.1:8000/docs**.

## Troubleshooting

- **`ModuleNotFoundError`** — make sure your virtual environment is
  activated (`(venv)` should show in your terminal prompt) before running
  `pip install` or `uvicorn`.
- **`FileNotFoundError: Missing model artifact`** — you skipped step 5.
  Run `python -m app.ml.train` from the project root first.
- **Port already in use** — run on a different port:
  `uvicorn app.main:app --reload --port 8001`.
